2026 年 2 月，我 star 了 [xrce/dots](https://github.com/xrce/dots)。当时惊为天人，仿佛打开了一扇门一样（当时真是这感受），我想着电脑还能这么玩？太酷了！它带我认识了 [sketchybar](https://github.com/FelixKratz/SketchyBar)，一个可完全自定义的状态栏，高颜值高自主性。同时这个文件也把作者的 kitty（一个好用的终端） 和 Neovim（一个好用的终端代码编辑器） 的配置一起搬过来了，这又是另外一扇门，带我进入了终端的世界，从这里开始，我爱上了TUI（终端UI，相对于GUI：图形化界面）。后来开始了我漫长的修图标、调间距、换方案、换终端、试 Agent之路，配置一点点变成了自己觉得最好用的样子。

当然，一开始只是觉得某些地方看着有点别扭，只想改一点小地方，后来一发不可收拾。就像最初的 Vibe Coding 一样，这玩意给的即时正反馈太足了，你看着自己改的东西在restart之后马上就是另一副样子，它上瘾啊！于是我开始沿着它持续不断地折腾。

现在把它们整理成了 [Asaki14/dotfiles](https://github.com/Asaki14/dotfiles)。如果你也想把 Mac 打磨得更顺手，可以看看我的配置是否能给你一些灵感，我希望我也能成为你的Xrce（开源精神？bushi）。这篇先讲全景和迭代，具体工具留到后续单篇。

## 修到能用，再改成自己的

最初借来的配置，并不是每处都适合我的环境。比如 sketchybar 按 App 显示的名字找图标，中英文名字对不上，就会退回默认图标。状态栏里的电量、音量和 Wi-Fi 点击逻辑错位，都是我手搓逐个修的，现在有AI了，那真是非常方便了，许愿机用起来。

那时记下的一条心得是：先看懂，再修改。AI 能解释源文件、建议改法，但不替我读官方文档，也不能替我判断哪些改动适合自己。修这些小问题的过程，也是逐渐认清这套配置怎么运转的过程，跟 AI Coding一样，最难的从来不是执行过程，而是知道自己真正想要什么并跟AI说清楚，这听起来简单但实际上知道并清晰描述是需要练习的。

接下来才是自己的偏好：窗口和状态栏的间距要对齐，终端换成喜欢的字体，主题切换时其他所有工具也跟着变。八月迁到 [omacosy](https://github.com/paulsp94/omacosy)时，之前几轮改动没有全部丢掉，而是把重要的自定义继续放进去，所以工具可能会变，但你的沉淀不会变，是一直跟着你的。

对我来说，舒服不只是好看。字要读得清楚，任务能集中处理，快捷键和工具联动也得自然。这里面有视觉偏好，也有每天切窗口、找任务时的具体感受，所以就跟前面说得一样，知道自己想要什么是一个长期过程。

## 四条线，逐渐连在一起


### 桌面与终端：从摆窗口到集中处理任务

窗口管理先从 [LOOP](https://github.com/mrkai77/Loop)换到 [yabai](https://github.com/asmvik/yabai)。yabai刚用的时候别提有多喜欢了，三种状态用快捷键切换，适配不同场景。它本身问题其实不大，但其实日常就用一种模式，并且mac屏幕小，两个APP各占一半看起来炫酷，但对我的眼睛不太友好+切换起来有点麻烦+要关 SIP（系统完整性保护），后来换 [Paneru](https://github.com/karinushka/paneru)，主要是被它类似 Hyprland 的横向平铺和虚拟工作区吸引。在同一桌面里横向排列窗口，再用快捷键切到特定工作区，不用反复切桌面找应用。当时分了杂务、工作、终端、浏览器四类，用了好一阵。

但 Paneru 偶尔需要重启，也遇到过好几次进程混乱，可能和其他工具不兼容。同时我逐渐发现，自己更喜欢高屏占比，让应用尽量铺满可用空间，看得清楚些。老了老了，就像我睡前一般都要泡脚一样（朋友说我已经是中年人了吗？）。引入 [omacosy](https://github.com/paulsp94/omacosy)后，发现 [AeroSpace](https://github.com/nikitabobko/AeroSpace)的工作区配置已经够用，用起来也稳定，又有现成预设，就顺便迁了过去。

终端也没有一次选定。Warp 的补全和文件侧栏很方便，但我遇到崩溃和 AI 功能不可用（地区原因，幸好当时没开，其实跟我的需求不是完全匹配），转而用 kitty 与 Neovim，之后又试了 Ghostty、cmux。当时记得我会同时开6个 Ghostty 窗口，分别跑 Coding Agent和 [yazi](https://github.com/sxyazi/yazi)，开多了电脑发热、卡顿，Paneru 宕机后还得重排五六个窗口。后来有一天逛 github trending的时候发现了当时只有几k star的 [Herdr](https://github.com/herdrdev/herdr)，可以吧把多个终端任务集中在一个工作区，对 Agent 还有特化适配，一眼相中，现在 star数已经是我发现它时的几十倍了。

后来文件管理 Yazi、任务管理 dooit 也放进终端，音乐则用 rmpc 与 MPD。十月为了在 Agent 工作之外用上 GUI，又开始体验 Tern。这些工具不只是换了外观，也改变了任务放在哪里、怎样在任务之间切换的习惯，现在用起来非常舒服，这也是我迭代的意义。

### AI 与工作流：工具在换，自己的做事方式也在改

我先用了 OpenCode 与 GitHub Copilot，随后尝试 Claude Code、Codex 等工具。工作流也试过 Everything Claude Code、Superpowers 和 GSD。到了 Pi，吸引我的是更轻的上下文，以及能按需求做扩展。

七月逐渐形成了先追问问题、再建项目、执行和审查的流程，也开始用 [firstmate](https://github.com/kunchenguid/firstmate)把任务隔离到不同的 Git worktree，也就是各自独立的工作目录，只和一个主 Agent 对话。九月转向 omp，看中模型接入、丰富的预设配置与账户轮换功能。十月并行任务少了，新会话的缓存复用不划算，便暂停 firstmate 派工，保留记忆与项目管理。

这条线后面会单独讲：哪些规则值得长期留下，哪些技能适合按需调用，以及记忆和上下文交接怎么做。

### 浏览器：标签管理和阅读，都是日常体验

浏览器走过 Zen → Firefox → 回到 Zen。最初为了扩展生态转去 Firefox，后来又因为标签页管理回到 Zen。Tabbit 也试过，但我遇到了卡顿和崩溃，没有继续用。

在 Zen 里，我用 [Nebula](https://github.com/JustAdumbPrsn/Zen-Nebula)与 [Zen Internet](https://github.com/sameerasw/my-internet)调整透明效果，用 [Darkreader](https://github.com/darkreader/darkreader)补阅读对比度，再加 Vimium 做键盘导航。浏览器里的 Agent 也有另一条尝试线，后来从操作用户 Chrome 会话转向 ego lite。透明网页、垂直标签和自动化各有取舍，留到浏览器篇展开。

### 笔记：从写一篇文章，到随时补一条

笔记从 Obsidian 转到 Logseq。我发现我很喜欢日记式随手记：想到什么马上写，再靠 tag 把同主题内容聚到一起，不必每次先想好应该放进哪一篇笔记，logseq完美满足了我的需求

之后搭了自建同步，也写了自己觉得好用的插件 [logseq-db-banner](https://github.com/Asaki14/logseq-db-banner)、[logseq-journal-time-prefix](https://github.com/Asaki14/logseq-journal-time-prefix)，已经开源。这一篇不展开插件和同步配置，笔记篇会讲记录方式为什么合适，以及哪些需求值得自己动手补。

## 壁纸是主题的一部分，阅读不能让步

八月试过 [Omarchy](https://github.com/omacom/omarchy)后，我深受启发，当时我在笔记里写过：“壁纸就是我的主题。”透明界面让状态栏、终端和背景更容易融在一起，换一张壁纸，就能改变整套桌面的感觉，这种一体化的高颜值高便利度的方案深得我心。

不过透明不是越多越好。提高终端的不透明度是必要的，可读性始终是第一，不能本末倒置。后来又把这件事拆得更细：美观来自字体、主题和背景，阅读则依赖不透明度和文字对比度。背景清晰时，文字也得从背景里分出来。

另一类改动很小，却会持续影响观感。状态栏的圆角贴合 Mac 的物理圆角，首尾图标到边缘的距离一致，窗口和状态栏的留白对齐，工作区高亮从整块填色改成描边。这些比单独换一个漂亮图标更接近我当时在调整的东西。

omacosy 则把换主题变成了联动：状态栏、壁纸、Ghostty 与边框一起切换，后面又让更多终端工具跟着主题走。外观不再只是每个工具单独选一个配色。

## 配置已开源，可以只装一部分

仓库在 [Asaki14/dotfiles](https://github.com/Asaki14/dotfiles)。这套 dotfiles，也就是保存各工具偏好的配置文件，按工具分模块，包含桌面主题、终端工具与 Agent 相关配置。


不带参数运行 `./install.sh`，会进入交互选择。也可以只选需要的模块，或用 `--all` 安装全部模块。已有冲突文件会先移到 `~/.dotfiles-backup/` 下的对应备份目录，再建立链接，仓库目录需要保留。

安装前请读仓库的[安装前须知](https://github.com/Asaki14/dotfiles/blob/main/README.zh-CN.md#安装前须知)。omacosy 会修改系统设置、加载后台服务并设置壁纸，文件备份不能还原这些系统设置。Agent 配置包含权限绕过设置，需要按自己的审批要求修改，预览命令不会实际安装。

不过我建议让你的 Agent 读仓库再帮你安装会比较好，毕竟它活在你的电脑上，最了解你的电脑情况。况且，这种事情上 AI 一般不会犯错误，人会，别问我怎么知道的。

起点感谢 xrce/dots。终点的omacosy 基于 paulsp94/omacosy，公开配置保留上游许可与署名。
